# Погода сейчас: первый запрос к HTTP API

**[Открыть погодный сервис](https://just-97.github.io/weather-api-lab/)**

Небольшой погодный сайт для занятия по ТРПО. Вы выбираете город, браузер отправляет один запрос к Open‑Meteo, а страница показывает температуру, влажность, ветер и местное время из ответа. Всё написано на HTML, CSS и обычном JavaScript. Для запроса не нужны аккаунт, API-ключ или свой сервер.

**Цель занятия:** отправить `GET`, найти его в Network, прочитать поле из JSON и показать его на странице. Для лабораторной достаточно знать, что такое переменная, функция и HTML-элемент. На самостоятельную работу отведите 25–35 минут.

## Быстрый запуск

На странице проекта на GitHub нажмите **Code → Download ZIP**. Если архив вам уже прислали, сразу распакуйте его.

1. Распакуйте ZIP целиком. Откройте распакованную папку, где лежит `index.html`.
2. Двойным щелчком откройте `index.html` в браузере, например в Chrome или Edge.
3. Оставьте «Минск» и нажмите **Показать погоду**. Через несколько секунд должны появиться числовые значения и надпись «Сводка загружена: Минск.». Для получения погоды нужен интернет.

Если браузер блокирует запросы с локальной страницы `file://`, можно запустить её через локальный HTTP-сервер. Если уже установлен Python 3, откройте терминал в папке с `index.html` и выполните:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

В Windows команда может начинаться с `py -3` вместо `python3`. Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) в браузере; для остановки сервера нажмите **Ctrl+C** в терминале. Этот сервер только раздаёт файлы страницы. За погодой браузер всё равно обращается к Open‑Meteo.

## Как это работает

**API** — правила, по которым одна программа обращается к другой. Для HTTP API правила описывают адреса, методы запроса, параметры и формат ответа. Здесь клиент — JavaScript в браузере, сервер — Open‑Meteo. Страница заранее знает координаты четырёх городов; Open‑Meteo получает координаты, а название города берётся из нашего списка.

```text
Клиент (браузер) → HTTP-запрос GET → Сервер Open-Meteo
                                          │
                                          ▼
Интерфейс (HTML) ← JavaScript ← HTTP-ответ с телом JSON
```

- **URL** указывает, куда обращаться. У `https://api.open-meteo.com/v1/forecast` домен — `api.open-meteo.com`, путь — `/v1/forecast`. После `?` идут параметры вида `имя=значение`; параметры разделяются `&`.
- **GET** означает, что клиент запрашивает данные. В URL мы передаём `latitude` и `longitude` (где нужна погода) и `current` (какие поля вернуть).
- **HTTP-ответ** содержит статус, заголовки и, в нашем случае, тело. `200` означает успех, `400` — некорректный запрос, `500` — ошибку на стороне сервера.
- **JSON** — текстовый формат передачи данных. После `await response.json()` получается значение JavaScript, и к вложенному полю можно обратиться через точку: `data.current.temperature_2m`.

Пример тела ответа, сокращённый для занятия. Реальные числа и время меняются:

```json
{
  "current": {
    "time": "2026-11-05T10:30",
    "temperature_2m": 5.4,
    "relative_humidity_2m": 95,
    "wind_speed_10m": 4.7,
    "weather_code": 3
  }
}
```

Из этого примера интерфейс получит `5,4 °C`, `95 %`, `4,7 м/с` и `10:30`. По коду `3` покажет «Облачно». В полном ответе также есть `current_units` с единицами измерения. Сохранённый [пример ответа для занятия без интернета](docs/example-response.json) можно открыть в редакторе.

## Лабораторная: от URL до страницы

Сначала посмотрите готовый сайт. Затем сделайте маленькую версию с одним городом и одной температурой. Работайте в отдельном файле `lab.html`, чтобы не менять готовый проект. После каждого шага сверяйтесь с ожидаемым результатом.

### 1. Посмотрите ответ API напрямую

Откройте [запрос температуры для Минска](https://api.open-meteo.com/v1/forecast?latitude=53.9&longitude=27.57&current=temperature_2m) в отдельной вкладке. Это GET-запрос. Найдите `current → temperature_2m` и `current_units → temperature_2m`. **Ожидание:** в первом поле число, во втором — `°C`. Формат отображения JSON зависит от браузера.

### 2. Отправьте тот же запрос из JavaScript

Создайте `lab.html` в папке проекта и вставьте в редакторе кода:

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Мой первый HTTP-запрос</title>
</head>
<body>
<h1>Погода в Минске</h1>
<button id="load">Загрузить</button>
<p id="output" role="status">Нажмите «Загрузить».</p>

<script>
  const button = document.querySelector("#load");
  const output = document.querySelector("#output");

  button.addEventListener("click", async () => {
    output.textContent = "Загружаем…";

    try {
      const url = new URL("https://api.open-meteo.com/v1/forecast");
      url.searchParams.set("latitude", 53.9);
      url.searchParams.set("longitude", 27.57);
      url.searchParams.set("current", "temperature_2m");

      const response = await fetch(url, { method: "GET" });
      if (!response.ok) {
        throw new Error(`HTTP ${response.status}`);
      }

      const data = await response.json();
      console.log(data);
      output.textContent = "Ответ пришёл. Откройте Console.";
    } catch (error) {
      output.textContent = `Не удалось загрузить погоду: ${error.message}`;
    }
  });
</script>
</body>
</html>
```

Сохраните файл именно с расширением `.html`. Откройте его в браузере двойным щелчком или по адресу `http://127.0.0.1:8000/lab.html`, если запустили локальный сервер. В инструментах разработчика откройте **Console** (в Chrome: меню **⋮ → Дополнительные инструменты → Инструменты разработчика**). Нажмите **Загрузить**. **Ожидание:** в консоли появится объект; раскройте `current` и найдите то же поле, что на первом шаге.

### 3. Покажите число на странице

Замените строку `output.textContent = "Ответ пришёл. Откройте Console.";` на:

```js
output.textContent = `${data.current.temperature_2m} ${data.current_units.temperature_2m}`;
```

Сохраните файл, обновите страницу и снова нажмите **Загрузить**. **Ожидание:** под кнопкой появится число с единицей измерения. Объясните соседу, откуда берётся каждая часть строки.

### 4. Вызовите и почините ошибку

Временно замените `53.9` на `999` в параметре `latitude`. Сохраните, обновите и нажмите **Загрузить**. **Ожидание:** под кнопкой появится сообщение с `HTTP 400`. Сервер доступен, но широта вне допустимого диапазона. Верните `53.9` и убедитесь, что температура снова появляется.

## Разбор кода готового сайта

Откройте [app.js](app.js). Сначала прочтите две функции, которые отвечают за HTTP. Остальной код связывает их с HTML.

| Строка кода | Что делает и зачем |
| --- | --- |
| `function buildWeatherUrl(city) {` | Принимает объект города из списка `cities`. |
| `const url = new URL("https://api.open-meteo.com/v1/forecast");` | Создаёт объект URL с адресом метода API. Пока запроса нет. |
| `url.searchParams.set("latitude", city.latitude);` | Добавляет широту выбранного города. |
| `url.searchParams.set("longitude", city.longitude);` | Добавляет долготу. `searchParams` сам собирает и кодирует строку запроса. |
| `url.searchParams.set("current", "temperature_2m,relative_humidity_2m,wind_speed_10m,weather_code");` | Просит четыре поля текущей погоды. В URL запятые могут выглядеть как `%2C`: это обычное URL-кодирование. |
| `url.searchParams.set("timezone", "auto");` | Просит сервис выбрать часовой пояс по координатам. |
| `url.searchParams.set("wind_speed_unit", "ms");` | Просит скорость ветра в метрах в секунду. Температура по умолчанию в °C. |
| `return url;` | Возвращает готовый адрес. |
| `async function getCurrentWeather(city) {` | Объявляет асинхронную функцию: она возвращает обещание результата (Promise), внутри можно использовать `await`. |
| `const url = buildWeatherUrl(city);` | Собирает URL перед отправкой. |
| `const response = await fetch(url, { method: "GET" });` | Отправляет GET и ждёт объект ответа с заголовками и статусом. `await` приостанавливает эту функцию, а страница остаётся отзывчивой. При сетевом сбое `fetch` отклоняет Promise. |
| `if (!response.ok) {` | Проверяет, что статус не входит в диапазон 200–299. `fetch` сам по себе не выбрасывает исключение для HTTP 400 или 500. |
| ``throw new Error(`Сервис погоды ответил с ошибкой HTTP ${response.status}.`);`` | Прерывает обработку и передаёт ошибку вызывающему коду. В сообщении сохраняется статус ответа. |
| `const data = await response.json();` | Читает тело ответа и разбирает JSON. Это отдельная асинхронная операция. |
| `const current = data?.current;` | Берёт раздел с текущими значениями; `?.` вернёт `undefined`, если `data` равно `null` или `undefined`. |
| `if (!current \|\| typeof current.time !== "string" \|\| …)` | Проверяет, что раздел есть и время пришло строкой. При отсутствии раздела следующие проверки не выполняются. |
| `![current.temperature_2m, current.relative_humidity_2m, current.wind_speed_10m].every(Number.isFinite)` | Убеждается, что температура, влажность и скорость ветра — конечные числа. `0` допустим, `null` — нет. |
| `throw new Error("В ответе API не хватает данных о погоде.");` | Останавливает обработку неполного ответа, даже если HTTP-статус успешный. |
| `return current;` | Возвращает только ту часть ответа, которую показывает сайт. |

Как данные попадают на страницу:

1. `document.querySelector("#weather-form")` находит форму по её `id`. `addEventListener("submit", …)` запускает обработчик отправки формы. `event.preventDefault()` отменяет обычную отправку с перезагрузкой страницы.
2. `cities[citySelect.value]` превращает выбранное значение, например `"minsk"`, в объект с координатами. `clearWeather(city)` убирает цифры предыдущего запроса. Пока ждём, `.disabled = true` блокирует список и кнопку.
3. `const current = await getCurrentWeather(city)` ждёт уже разобранные данные. `showWeather(current)` обновляет элементы: `.textContent` записывает обычный текст, а `.toLocaleString("ru-RU")` форматирует числа с десятичной запятой. `current.time.slice(11, 16)` берёт пять символов времени (`10:30` из `2026-11-05T10:30`). `weatherDescription` переводит числовой код в подпись.
4. `catch (error)` показывает понятное сообщение. Сетевой сбой, HTTP-ошибка и невалидный JSON возникают на разных шагах: в `fetch`, в проверке `response.ok` и в `response.json()` соответственно. Подробности остаются в Console.
5. `finally` возвращает кнопку и список в рабочее состояние и после успеха, и после ошибки.

В [index.html](index.html) находятся форма и места под данные; `defer` запускает `app.js` после разбора HTML. [styles.css](styles.css) отвечает только за внешний вид.

## DevTools: найдите запрос в Network

1. В готовом сайте откройте инструменты разработчика и вкладку **Network** («Сеть»). Выберите **Fetch/XHR**, включите **Disable cache**. Очистите список кнопкой **Clear**.
2. Выберите Минск и нажмите **Показать погоду**. В списке появится `forecast?…`. Откройте эту строку.
3. В **Headers → General** найдите **Request URL**, **Request Method: GET** и **Status Code: 200**. В **Payload → Query String Parameters** или прямо в URL найдите `latitude`, `longitude` и `current`.
4. В **Response** найдите исходное тело JSON. В **Preview** его можно раскрыть как дерево. Сравните значение `current.temperature_2m` с числом на странице.
5. Выберите другой город и отправьте запрос. Сравните координаты двух запросов. Затем переключите ограничение сети на **Offline**, снова нажмите кнопку и посмотрите на ошибку. Верните **No throttling** и повторите запрос, чтобы увидеть восстановление.

Если запрос не появился, проверьте, что Network открыт до клика. Если видите HTTP-статус, сервер ответил. Если браузер пометил запрос как `(failed)` без статуса, посмотрите Console: это может быть сбой сети или ограничение браузера. [Справка по Network](https://developer.chrome.com/docs/devtools/network/reference/).

## Проверка работы

| Сценарий | Действие | Ожидаемый результат |
| --- | --- | --- |
| До запроса | Открыть страницу и не нажимать кнопку. | На карточке прочерки; запроса `forecast` нет. |
| Успех | Запросить Минск. | GET со статусом 200. Температура, ветер и влажность совпадают с `current` из Response, с учётом формата чисел. |
| Другой город | Выбрать Тбилиси и нажать кнопку. | В запросе `latitude=41.72`, `longitude=44.79`; в карточке «Тбилиси». Не требуется, чтобы температура отличалась. |
| Загрузка | В Network выбрать медленный профиль и нажать кнопку. | Видно «Загружаем погоду…». Кнопка и список временно недоступны. |
| Нет сети и восстановление | После успешной загрузки включить Offline, повторить запрос, затем вернуть No throttling и повторить ещё раз. | Ошибка связи, прежние числа заменены прочерками, кнопка снова доступна. После восстановления сети появляются данные. |
| HTTP-ошибка | В своей копии `app.js` задать Минску `latitude: 999`, сохранить, обновить и запросить Минск. Затем вернуть `53.90`. | HTTP 400 в Network и в сообщении на странице. После исправления приходит 200. |
| Клавиатура и узкий экран | Сузить окно; клавишей Tab перейти к списку и кнопке, отправить запрос клавишей Enter. | Элементы выстроены в одну колонку, фокус виден, кнопка работает, страница не прокручивается горизонтально. |

**Что сдавать:** `lab.html`, скриншот или описание одного успешного запроса из Network (метод, статус и поле температуры) и объяснение, почему нужен `response.ok`.

## Мини-задания

1. **Повторить.** В `lab.html` запросите влажность вместе с температурой и выведите обе величины. Подсказка: `temperature_2m,relative_humidity_2m`. Проверьте второе поле в Response.
2. **Изменить.** Добавьте свой город в готовый сайт. Нужны новая запись в `cities` и `<option>` с таким же ключом в `value`. Найдите координаты центра города и подтвердите их в Network.
3. **Объяснить.** Чем различаются `await fetch(...)` и `await response.json()`? Почему при HTTP 400 `fetch` может завершиться успешно, а код всё равно попадёт в `catch`?
4. **Усложнить.** Покажите «ощущается как» в карточке. Найдите `apparent_temperature` в документации, добавьте поле к `current` и выведите его с единицей измерения. Проверьте, что значение совпадает с Response.
